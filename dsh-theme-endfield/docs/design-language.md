# 设计语言：终末地现场工程系统 → DSH 令牌

本文说明皮肤的设计决策与它落到 DSH 设计系统上的具体位置，供后续微调时参考。

参考基线是 Hypergryph 公开作品里可归纳的 “field engineering system” 视觉规律
（墨色/纸白/信号黄、直角与小切角、1px 结构线、等宽数据、单一强调色、地形等高线），
不复制任何美术资源、字体或商标。

## 1. 两套主背景（深 / 浅）

主背景有**深、浅两个变体**，来自同一套色阶，用一个 localStorage 开关即可来回切：
`localStorage['dsh-endfield-surface'] = 'light' | 'dark'`，刷新生效（当前默认 **light**）。

| | 浅色（默认） | 深色 |
|---|---|---|
| 底色 | `#f2f2f0` 纸白 | `#131312` 灰黑 |
| 文字 | `#131312` 墨（次级 `#3a3a38` / 三级 `#565654` / 注释 `#6f6f6c`） | `#f2f2f0` 纸白（次级 `#bcbcb6` / 三级 `#94948e` / 注释 `#63635e`） |
| 面板 / 浮层 | 纯白面 + 墨色描边 + 实投影 | `#1d1d1b → #2b2b28` |
| 输入框 | 纸白面板 + 墨字 + 墨色圆钮 | 浅灰面板 + 亮字 + 纸白圆钮 |
| 等高线 | 墨色 20% / 计曲线 `rgb(122 108 0 / 72%)` | 纸白 11% / 计曲线信号黄 |
| 结构线 | 墨色 18/26/34/46% | 纸白 9/15/24/36% |
| 开屏动画 | 纸白装载屏 + 墨色等高线与文字 | 原灰黑装载屏 |
| 黄栏 / 黄带 | 两版一致 | 两版一致 |

切换方式：**设置 → 通用 → 外观**（浅色 / 深色 / 跟随系统）即可，改完立刻生效、无需刷新；
需要绕过偏好做 A/B 对比时，`localStorage['dsh-endfield-surface'] = 'light' | 'dark'` 会把它钉死。

实现方式不是写第二套配色，而是**把两条中性色阶整条镜像**（`src/palette.js` 的 `mirrorFamily`）：

- 色阶里低序号是纸端、高序号是墨端；「深色模式」的别名映射是 `文字 = bluish-50`、`底 = bluish-950`。
  把这两条色阶按停靠点整体对折（`00 ↔ 1000`、`50 ↔ 950`…），同一套别名就落在「浅底 + 深字」上。
- **只镜像表面色阶**（`neutral-bluish`、`neutral`）；`deepseek`（信号黄）等语义色阶保持原样，
  否则强调色会被折成暗橄榄。
- 写死为字面量（非色阶引用）的别名——边框、交互底色、遮罩、骨架、工具条、气泡、文字层级——
  在 `ALIASES_LIGHT` 里另给一套墨色值。**每个令牌必须两个模式都有值**：一层令牌表是
  `{ light, dark }` 成对的，只在一个模式里出现的令牌会让另一个模式拿到 `undefined`（直接抛错）。
- 样式表里写死的颜色（结构线、等高线、视口外框、角标、面板、输入框面、气泡、焦点环、开屏）
  收在 `html[data-endfield-surface="light"] { … }` 一节里，并顺带把 `color-scheme` 切成 light。

**一个令牌层，两个模式槽**：`combineSurfaces()` 把两套表面合成**一层**——每个令牌带
`{ light: 浅色表面值, dark: 深色表面值 }`，主题服务按**当前激活主题的 colorScheme** 取槽。
所以「设置 → 外观」切浅/深时皮肤立刻跟着换，而**不需要重新注册令牌层**：
在 `theme/change` 回调里重新 `overrideTokens` 会在 emit 过程中再次 publish，直接抛
`Cannot read properties of undefined`。

**踩过的坑**：`mirrorFamily` 起初按 `Object.keys` 的下标配对，结果全错位。原因是 JS 会把
`"50"`、`"100"` 这类**整数样式的键按数值升序排在最前**，而 `"00"` 不算整数样式键、被排到最后——
键的顺序并不是色阶的书写顺序。镜像前必须先按数值排序。

**为什么模式属性仍固定 dark**：色阶是照着「深色模式」的别名映射写的，表面明暗由**变体**决定、
不由模式标志决定；因此两版都强制 `data-ds-dark-theme`（并把 `color-scheme` 按变体覆盖），
偏好本身留给「外观」那一行去写。

## 3. 令牌映射（`src/palette.js`）

DSH 的组件样式几乎全部走 `--dsw-*`，其中 `--dsw-alias-*` 由 `--dsw-static-*` 色阶派生。
因此皮肤的策略是**换色阶 + 覆写少量语义别名**，而不是逐组件写样式：

| 色阶族 | 原语义 | 皮肤语义 | 影响面 |
|---|---|---|---|
| `--dsw-static-neutral-bluish-*` | 冷蓝中性 | 暖中性墨/纸阶 | 背景、文字、边框、浮层（主体） |
| `--dsw-static-neutral-*` | 纯中性 | 暖中性（同调） | 滚动条、工具条、行内代码 |
| `--dsw-static-deepseek-*` | 品牌蓝 | **信号黄阶** | 链接、主色、业务态、进行中指示 |
| `--dsw-static-green/amber/red-*` | 成功/警告/错误 | 校验绿 / 警示橙 / 告警红 | 状态语义 |
| `--dsw-static-blue-*` | 冷蓝 | 中性钢灰（低饱和） | 浅色模式残留引用 |

别名层只覆写语义确有变化者（`src/palette.js` 的 `ALIASES`）：

- `--dsw-alias-brand-primary` / `--dsw-alias-brand-text` → 信号黄（深色默认是纸白）
- `--dsw-alias-button-primary-hover` / `-dimmed` → 压暗信号黄 / 暗橄榄
- `--dsw-specific-sidebar-fill` → `#0d0d0c`（注意：真实令牌名是 `--dsw-specific-*`，没有 `alias` 段）
- `--dsw-alias-border-l1..l4`、`-inverted*` → 纸白透明度阶梯
- `--dsw-alias-interactive-bg-hover*` → 中性/信号黄/危险三种悬停色
- `--dsw-alias-bg-mask-*`、`-skeleton`、`-button-tool-bar-*`、`-state-warn-label`、`-scrollbar-hover-*` → 按暖中性微调

覆写层通过 `ctx.theme.overrideTokens(source, tokens)` 注册。每个令牌必须给出
`{ light, dark }` 两个值（层是按模式选槽的），本皮肤用这两个槽承载**两套表面**
（`combineSurfaces()`）：`dark` 槽 = 深色表面值、`light` 槽 = 浅色表面值，
于是主题服务按当前激活主题的取色方案自动选槽，皮肤因此与 DSH 主题系统是协作关系，
而不是覆盖式注入。

## 4. 几何

| 规则 | 实现 |
|---|---|
| 全站圆弧 | `--dsw-corner-shape: round`（真正的圆弧圆角；基础主题原本是 `superellipse(1.5)` 的方圆形）。圆形元素本来就成对声明 `corner-shape: round`，不受影响 |
| 控件圆弧 | `button / input / textarea / select / summary / code / pre / role="tab" / 列表行` → `border-radius: 10px` |
| 面板圆弧 | 对话框/菜单/列表/提示 → 16px 圆角 + 1px 描边 + 极浅渐变，取消玻璃模糊与重投影 |
| 聊天面弧形 | 输入框 20px + 浅灰渐变底；输入区内按钮 `999px` 圆形、芯片胶囊形；用户气泡 22px。聊天框周边**没有黄色**：发送键是纸白圆钮 + 墨色图标，输入区焦点环与芯片悬停都用纸白，框边不出现任何黄色线条 |
| 视口外框 | 内缩 6px 的 1px 外框，圆角 14px；四角括号仍是直角标记（测绘标记语言） |
| 侧栏—顶带圆角过渡 | 二者交汇处的 90° 内角补一块 34px 的四分之一圆（concave fillet），且元素向上多留 16px 实色黄盖住黄带尾部的渐隐区——否则圆弧与黄带之间会露出一道底色空隙；位置由运行时量出来的 `--ef-rail-w` / `--ef-band-h` 决定 |
| 滚动条 | 滑块去圆角（方形），宽度沿用 `--dsh-scrollbar-width`；黄栏内改用墨色滑块 |
| 焦点 | 全局 `:focus-visible` 2px 信号黄描边 + 2px 偏移 |
| 选区 | 信号黄底 + 墨色文字 |

## 5. 排版

- 界面字体：`Segoe UI Variable Text → Segoe UI → Microsoft YaHei UI → PingFang SC → system-ui`
- 数据/代码字体：`Cascadia Mono → JetBrains Mono → SFMono-Regular → Consolas`
- 数字：`font-variant-numeric: tabular-nums`（索引、耗时、token 计数对齐）
- 微标签：`.eyebrow / .groupTitle / .panelTitle / .sectionTitle` + 品牌字标 → 大写 + `letter-spacing: .1em`（中文表现为字间透气）
- 表头 `th` → 大写 + 字距 + 1px 底线；标题 `h1..h3` 轻微正向字距

## 6. 质感与外框（`apply()` 注入的 chrome 层）

`[data-endfield-chrome]`：`position: fixed; pointer-events: none; aria-hidden="true"`，
追加在 React 根节点旁边，任何一次渲染都不会回收它：

- `[data-ef="contour"]`：地形等高线场（见第 9 节）
- `[data-ef="wash"]`：一片极浅的四周压暗（唯一的背景层，没有条纹/网格/辉光）
- `[data-ef="frame"]`：内缩 5px 的 1px 视口边框
- `[data-ef="corner"] × 4`：15px 信号黄角标，2.4s 呼吸（`prefers-reduced-motion` 下静止）

## 7. 调色模式锁定

- 皮肤不改变「外观」偏好本身，只**固定调色模式属性**：`body` 上始终带 `data-ds-dark-theme`，
  `documentElement` 上始终 `color-scheme: dark`。
  原因是色阶是照着深色模式的别名映射写的，若让基础样式表落到浅色块，
  别名会解析成另一套值（实测会得到白字白底）。
- 断言走 DOM（属性 + `MutationObserver` 兜底），不走 `setTheme`：
  durable 设置读回发生在插件激活之后，会把手写偏好再采纳一次。
- 表面变体与模式标志解耦：见第 1 节，偏好由「设置 → 外观」写、皮肤读。

### 浮层被盖住的坑（设置点了没反应）

给应用容器加 `position: relative; z-index: 0` 会**创建层叠上下文**。设置面板这类浮层
（`position: fixed; z-index: 1000`）如果渲染在这个子树里，它的 `z-index` 就只在子树内有效——
后出现的会话列会把整个浮层盖住，表现就是「点设置没反应」（实测 `elementFromPoint`
命中的是会话滚动容器而不是面板）。

所以黄带与侧栏黄块都改成**不需要伪元素、不需要定位**的画法：

- 黄带：黄色直接画在 `header` 自己的 `background-color` 上（内容自然压在它之上）。
- 侧栏左上角圆角：外层 `sidebarCol` 铺主背景色、内层根容器铺黄并加 `border-top-left-radius: 76px`
  ——`border-radius` 只裁元素自己的背景、不建层叠上下文，同样安全。

### 弹窗的第二个坑（深色下「很黑，什么都看不见」）

同一个原因还带来第二个副作用：设置弹窗的 DOM **就在侧栏子树里**，于是它继承了黄栏那套
「标签/边框令牌 = 墨色」的反相。浅色变体下这恰好是对的（墨字 + 白面板），
深色变体下就成了**墨字压在暗面板上**——实测弹窗 `color: rgb(13,13,12)`、
面板 `rgb(35,35,32)`，整块看着就是一团黑。

修法：在 `[role="dialog"]`（含 `alertdialog`）上把页面级令牌**显式恢复**回来，
按变体各给一套（深色 = 纸白文字、浅色 = 墨色文字），并顺带把面板底色抬起来：

| 层 | 深色变体 | 浅色变体 |
|---|---|---|
| `--dsw-alias-bg-layer-1` | `#232321` | `#ececea`（镜像色阶） |
| `--dsw-alias-bg-layer-2`（弹窗面） | `#2a2a28` | `#e4e4e1` |
| `--dsw-alias-bg-layer-3` | `#333330` | `#d8d8d4` |
| 弹窗面 | 层 2 + 墨色 28% 描边 + 实投影 | **纯白** + 墨色 34% 描边 + 实投影 |

深色那三层不能直接改色阶：浅色表面是按镜像取值的（`875 ↔ 75` 等），
提高深色端会同时把浅色端拉暗。所以在 `ALIASES`（深色层）里单独给值，
浅色层继续走镜像色阶。模态遮罩也从 62% 收到 50%，免得背景被压成纯黑。

复测：深色 `panelBg rgb(42,42,40)` / `panelColor rgb(242,242,240)` / 面板可绘制 ✓；
浅色 `panelBg rgb(255,255,255)` / `panelColor rgb(19,19,18)` / 面板可绘制 ✓。

皮肤不写「外观」偏好，只固定调色模式属性（`data-ds-dark-theme` + `color-scheme`），
表面明暗由**变体**决定、变体跟随偏好（见第 1 节）。引导脚本这一层的做法是：

1. **Host 半边**在 index.html 的 `<body>` 开头追加一行引导脚本，在首屏绘制前就写上
   `data-ds-dark-theme` 与 `color-scheme: dark`（避免浅色偏好下的白屏闪烁）。
   注入行按监听器注册顺序渲染，ui-theme 自己的引导行会按“持久化偏好”写值、可能写回
   `light`，因此这一行**立即断言一次、并在 `setTimeout(0)` 后再断言一次**，与顺序无关。
2. **客户端半边**在 `apply` 时断言同一组字段，并监听 `theme/change`；
   `MutationObserver` 会在 ui-layout 的 presenter 摘掉该属性时立刻补回。
3. 样式表里 `html:root { color-scheme: dark !important }` 兜住原生控件与滚动条，
   浅色变体再用 `html[data-endfield-surface="light"] { color-scheme: light !important }` 覆盖回来。
4. 偏好本身留给「设置 → 外观」写；插件只在首次加载（有 A/B 钉死开关时除外）
   把偏好播成 `light` 一次，好让设置里的选中项与皮肤一致。
   之后不再改写偏好——反复写偏好会与其它浏览器的设置作用域形成回环。

## 8. 绑定的 DOM 钩子（升级排查用）

皮肤只用两类选择器：

**语义钩子（稳定）**：`[role="dialog"|"menu"|"listbox"|"tooltip"|"tab"]`、`button/input/textarea/pre/code/th`、
`[data-composer-card]`、`[data-composer-chip]`、`[data-composer-stats]`、`[data-conversation-scroll]` 等。

**CSS Module 类名片段（随 DSH 版本可能变化）**：
`_sessionRow`+`_selected`、`_panelActive`、`_rowActive`、`_optionSelected`、`_newSession`、
`_brandName`、`_eyebrow`、`_groupTitle`、`_panelTitle`、`_sectionTitle`、`_themeCube`；
开屏动画读取欢迎页标语用 `_titleGroup`（读不到就退回产品字标，动画照常跑）。

若升级后某个细节失效，先在浏览器里确认该类名是否还存在，再改 `src/endfield.css` 对应小节。

## 9. 等高线场（地形／测绘语言）

终末地把“测绘”当作世界观的一部分：地形线、计曲线、刻度条都属于这套语言。
插件用同一个确定性生成器（`contourRing` / `contourSvg`）产出两块场，开屏与主界面共用同一套规则。

**生成规则**

- 一个「山头」= `[cx, cy, rx, ry, levels, seed]`；第 `n` 圈的半径系数是 `0.34 + 0.15n`，
  圆心每圈偏移 `(+2.2, −1.4)`，所以等高线会“压向坡面”而不是同心圆。
- 每圈半径叠加三个谐波（3/5/2 次，振幅 0.17/0.09/0.05，相位随圈数递增），得到自然的凹凸；
  128 点采样成折线，`vector-effect="non-scaling-stroke"` 让线宽不随缩放变化。
- **线宽**：普通等高线 `1.7px`、计曲线 `2.4px`（1px 太细，读不出“地形”的感觉；
  计曲线更重也是真实地形图的规则）。开屏那块场稍收一档：`1.5px` / `2.1px`。
- **每 5 条一条计曲线**（`data-ef-index`）用信号黄（浅色变体用更深的 `rgb(122 108 0 / 72%)`）
  ——这是真实地形图的索引等高线规则；没有任何随机数：同一份 peaks 每次刷新画出同一张图。

**两块场的分工**

| | 主界面 `[data-ef="contour"]` | 开屏 `[data-ef="s-contour"]` |
|---|---|---|
| peaks | 4 处贴边 + 2 处落在画面内（左下内容区、右上角） | 4 处，主山头正对字标 |
| 遮罩 | 径向渐变：中心 20% 不透明度 → 边缘全量（中间只压淡，不抹掉） | 无遮罩 |
| 线色 | 纸白 11% / 计曲线信号黄 20% | 纸白 11% / 计曲线信号黄 19% |
| 运动 | 120s 极慢漂移 + 1.5% 缩放（`ef-drift`，reduced-motion 下静止） | 由山头向外逐圈自绘（每圈 900ms，错峰 22ms） |
| 结局 | 常驻纹理 | 动画结束随整层移除 |

**它是唯一的纹理**：底面是平涂灰黑（`[data-ef="wash"]` 只加一片四周压暗），
没有任何条纹、网格或扫描线跟等高线抢画面——线条的对比度全部留给地形本身。

## 10. 信号黄侧栏与顶部黄带

黄色承担两个身份：内容区里的强调色，以及侧栏那一片**实色黄**。

**侧栏（`[class*="sidebarCol"]`）**

- 整列填 `#fffa00 → #f6f000`，右缘一条墨色 22% 结构线与内容区分开。
- **左上角是一个 76px 正圆角**（凸向角、圆心在黄块内侧的四分之一圆）：
  外层 `sidebarCol` 铺主背景色（`--ef-page`：深色变体 `#1a1a1a`、浅色变体 `#f2f2f0`），
  内层根容器（`sidebarCol > * > [class*="_root"]`）铺黄色渐变并加圆角：

  ```css
  /* 外层：主背景色 */           [class*="sidebarCol"] { background-color: var(--ef-page) !important; }
  /* 内层：黄块 + 圆角 */        [class*="sidebarCol"] > * > [class*="_root"] { border-top-left-radius: 76px; }
  ```

  圆角切掉的那块（左上角四分之一圆之外）自然露出外层的主背景色，右上角不受影响。
  早先写成"圆心在角上的 `radial-gradient`（圆内不透明、圆外透明）"是**反的**——
  那是从角上挖掉一个圆（凹口），看起来像被咬了一口；圆角是凸的。
  `border-radius` 只裁元素自己的背景、不建层叠上下文，所以这个画法同样不会困住浮层。
- 半径取 76px 是量出来的上限：圆弧在 x=20px（字标图标左缘）处只有 ≈25px 高，
  正好从图标上方擦过——再大就会切进 logo。因此**不需要移动任何内容**，
  字标行、新会话按钮、列表全都留在原位。
- 实测复核（逐列扫第一颗黄像素）：x=24→20.6、x=40→9.1、x=56→2.7、x=68→0，
  与 R=76、圆心在 (76,76) 的圆方程 `y = R − √(R² − (R−x)²)` 完全吻合——确认是正圆弧圆角。
- 左上角那个 HUD 角标落在圆角外的底色上：深色变体用信号黄、浅色变体用墨色（左下角仍在黄块上，用墨色）。
- **输入光标**：浅色变体下自带的白色光标在纸白输入框上看不见，改成**深暗金** `caret-color: #6f6a00`
  （信号黄的暗调，纸白底上对比度约 5.5:1；越接近 `#fffa00` 越糊）；深色变体沿用品牌黄。
  实测：输入框内 `contenteditable` 计算值 `rgb(111, 106, 0)`，全应用可编辑元素一致。
- 栏内**整体反绑令牌**：`--dsw-alias-label-*`、`--dsw-alias-border-l*`、`--dsw-alias-interactive-bg-*`、
  `--dsw-alias-brand-primary`、滚动条令牌全部换成墨色／墨色透明度。子元素只要读 `var()` 就自然变深色，
  不需要逐组件写规则——这是把一整个区域反相的最省力做法。
- 几个必须单独处理的（它们的颜色不走令牌）：选中会话行的信号条改墨色、
  `_newSession` 主按钮**去掉外圈描边**（只留文字与图标）、视口左侧角标上黄（落在暗底）下墨（落在黄块）。

**顶部黄带（会话头部）**

- 会话头部浮在滚动区之上（内容会从它下面穿过），所以黄带用**不透明实色黄**（平涂、无渐变）：
  半透明黄会把穿过头部的内容“洗白”（浅色文字压在黄上既不是深色也不是白色），
  不透明黄则把内容干净地盖住，下沿是一条干净的分界。
- 关键坑：**`color` 是继承的计算值**。只重绑 `--dsw-alias-*` 不会给子元素重新着色——
  子元素从 body 继承到的仍是已经算好的浅色。所以黄带额外做两件事：
  1. 在头部元素上直接写 `color: #0d0d0c`（让所有「自己没写颜色」的子元素变墨色）；
  2. 对少数自己写了颜色的元素（激活页签用的是信号黄、工具图标用的是纸白）逐个覆盖成墨色，
     并把页签的指示条改成一条笔直的墨色横线（去掉应用自带的圆角与内阴影叠加）。
- 作用域用 `header[class*="_header"]:has([class*="_tabs"])` 锁定“带页签的那个头部”，
  避免误伤右侧栏等其他头部；`:has()` 不可用时整段失效，退化为普通深色头部。

**侧栏与顶带的连接处（圆弧过渡）**

- 黄栏在左、黄带在上，两者在内容区左上角交汇出一个 90° 内角。补一块 34px 见方的
  `radial-gradient(circle at 100% 100%, transparent R, yellow R)` —— 即四分之一圆的内凹圆角
  （concave fillet），黄色就从侧栏「流」进顶带，而不是硬碰。元素还要**向上多留 16px**
  （`top: calc(var(--ef-band-h) - 16px)`、高度 `R + 16px`）：黄带最后几个像素是化进底色的渐隐，
  不盖住它，圆弧与黄带之间就会露出一道底色空隙。
- 位置不能写死：侧栏宽度可拖拽、头部高度会随内容变化。插件每 600ms 量一次
  `[class*="sidebarCol"]` 的宽与 `header[...]:has([_tabs])` 的高，只在数值变化时写
  `--ef-rail-w` / `--ef-band-h`，并据此决定是否显示 fillet（新会话态没有带页签的头部 → 不显示）。
  用轮询而不是 ResizeObserver，是因为 chrome 层在 shell 渲染之前就装好了，
  早期观察不到还不存在的元素，而会话切换会把头部重新挂载。

## 11. 动效

- 交互反馈：沿用 DSH 的 `--ds-transition-duration*`（0.1/0.2/0.3s）
- 常驻循环：角标呼吸 2.4s、等高线场漂移 120s；`prefers-reduced-motion: reduce` 下都静止
- 不引入位移/缩放动画，避免与流式输出、工具卡展开的既有动效打架

### 开屏动画序列

参考官方站点装载屏（近黑 + 居中字标 + 等宽小字 + 块状指示）与其“满屏信号黄”过场：

| 时间 | 画面 | 实现 |
|---|---|---|
| 0ms | 平涂灰黑装载屏出现（等高线场 + 四周压暗） | `[data-endfield-splash]` + `[data-ef="s-contour"]` |
| 0–1100ms | 地形等高线**逐圈自绘而出**（由山头向外，每圈错峰 22ms） | `pathLength="1"` + `ef-s-draw` 的 `stroke-dashoffset: 1 → 0` |
| 60–680ms | 一条 3px 信号黄标定线自左扫过中线，留下 1px 结构线 | `[data-ef="s-scan"]::after` 的 `ef-s-scan` |
| 120/190/260/330ms | 四角括号依次“扣上”（`scale(1.9) → 1`） | `[data-ef="s-corner"]` 的 `ef-s-snap` + 错峰 `animation-delay` |
| 180ms | 字标上方的信号黄棱形放大出现 | `[data-ef="s-prism"]` |
| 240–880ms | 主标（CJK 标语）与拉丁微标签横向遮罩揭示 | `ef-s-reveal`：`clip-path: inset(0 100% 0 0) → inset(0)` |
| 520ms | 左下读表淡入：五格活动指示 + `MODULES n · REV xxxx` | `[data-ef="s-readout"]` |
| 装载中 | 五格以 `steps(1)` 跑动（仪表感，不用缓动） | `ef-s-chase` |
| 界面就绪 | 五格依次点亮为信号黄（真实就绪信号，不是定时器） | `[data-phase]` + 逐格 `transition-delay` |
| +240ms | **① 黄幕从右上角出现**，右缘 **10% 宽（约十分之一屏）**的窄柱竖直延伸到底 | `ef-s-rise`：`clip-path: inset(0 0 100% 90%) → inset(0 0 0 90%)` |
| +140ms | 黄幕驻留 | `SPLASH_FILL_HOLD` |
| +340ms | **② 整块向左滑动**，直到铺满全屏 | `ef-s-slide`：`clip-path` 左侧 90% → 0%；墨色字标残影在滑开后才淡入（窄柱阶段放不下） |
| +380ms | **③ 渐变溶解（从右往左）**：整层（黄幕 + 装载屏）被遮罩化掉——遮罩右端的透明区从右侧进入、向左推进，所以是右边先化、左边最后化掉，露出界面 | 整层常驻 `mask-image` + `ef-s-dissolve`（`mask-position: 0% → 100%`，`opacity: 1 → 0`） |

规则：

- 溶解必须作用在**整层**而不是只作用在黄幕上：只化黄幕会把下面的装载屏（等高线 + 字标 + 读表）
  重新露出来，等于「加载屏闪一下再切界面」；整层化掉才是直接露出应用。
- **文案必须真实**：主标取界面自己的欢迎标语（`[class*="_titleGroup"]` 渲染后读取，因此跟随语言），
  副标是产品字标，读表取 `window.__DSH_BOOT__` 的真实构建号与模块数；
  没有编造的进度百分比或伪造遥测。
- 结束时机由“界面真的渲染出来了”决定（`#root` 有子节点或出现 shell 帧），最短展示 1150ms 保证动画读得完，
  最长等待 6s 兜底；点击/按键/滚轮可跳到擦除（下限 420ms）。
- `prefers-reduced-motion: reduce` 时整段不创建；插件卸载或 HMR 时 `finish()` 会清掉所有定时器并移除节点。
